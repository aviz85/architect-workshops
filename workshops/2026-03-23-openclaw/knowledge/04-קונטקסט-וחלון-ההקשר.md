# פרק 4: קונטקסט - חלון ההקשר ואיך לנהל אותו

## מה זה "חלון הקונטקסט"?

**חלון קונטקסט** (Context Window) הוא הכמות המקסימלית של מידע שמודל AI יכול "לראות" בפעם אחת. זה כמו שולחן עבודה - כמה גדול השולחן, כמה דברים אפשר להניח עליו.

כשהשולחן מתמלא - OpenClaw מבצע **Compaction** (כיווץ).

---

## מה נכנס לקונטקסט?

```
┌─────────────────────────────────────┐
│         CONTEXT WINDOW              │
├─────────────────────────────────────┤
│ System Prompt:                      │
│  - רשימת כלים                       │
│  - רשימת Skills                     │
│  - קבצי Workspace (AGENTS.md...)   │
│  - תאריך/שעה                        │
│  - הגדרות Sandbox                   │
├─────────────────────────────────────┤
│ היסטוריית שיחה:                     │
│  - הודעות המשתמש                    │
│  - תשובות הסוכן                     │
│  - תוצאות כלים                      │
├─────────────────────────────────────┤
│ תוכן נוכחי:                         │
│  - תמונות / אודיו שצורפו            │
│  - תוצאות חיפוש                     │
│  - תוכן קבצים שנקראו               │
└─────────────────────────────────────┘
```

## פקודות לניהול קונטקסט בצ'אט

```
/status          → כמה מלא חלון הקונטקסט?
/context list    → מה מוזרק + גדלים
/context detail  → פירוט עמוק: כל קובץ, כל כלי
/usage tokens    → הוסף footer של שימוש לכל תשובה
/compact         → כווץ היסטוריה ישנה ידנית
```

## Compaction - מה קורה כשהקונטקסט מתמלא?

כשחלון הקונטקסט מגיע לגבולו, OpenClaw **מכווץ** את ההיסטוריה הישנה:

1. **מסכם** את השיחות הישנות לתקציר קצר
2. **שומר** את התקציר ב-JSONL (נשמר לצמיתות)
3. **שומר** את ההודעות האחרונות (לא נוגע בהן)
4. **ממשיך** כאילו כלום לא קרה - אבל עם חלון פנוי

```
לפני:  [ישן ישן ישן ישן | אחרון אחרון]
אחרי:  [תקציר           | אחרון אחרון]
```

### Compaction אוטומטי
- ברירת מחדל: **מופעל**
- אתה תראה: `🧹 Auto-compaction complete`
- מודל שונה לcompaction אפשרי (חסכוני יותר)

### Compaction ידני
```
/compact
/compact "Focus on decisions and open questions"
```

### ההבדל: Compaction vs Pruning

| Compaction | Session Pruning |
|-----------|-----------------|
| מסכם ושומר בדיסק | מוחק מ-RAM בלבד |
| פועל על כל ההיסטוריה | פועל רק על תוצאות כלים |
| שומר לצמיתות | נעשה מחדש בכל בקשה |

## Context Engine - מי אחראי על הקונטקסט?

**Context Engine** הוא המנגנון שמחליט מה נכנס לקונטקסט ואיך.

OpenClaw מגיע עם engine מובנה (`legacy`). Plugin יכול להחליף אותו.

### שלבי חיי ה-Engine
1. **Ingest** - כשהודעה חדשה מגיעה
2. **Assemble** - לפני כל ריצה: בנה את הקונטקסט
3. **Compact** - כשהחלון מלא
4. **After turn** - אחרי כל ריצה

---

## Session Pruning - גיזום כלים ישנים

**Pruning** הוא מנגנון שחוסך tokens על ידי **הסרת תוצאות כלים ישנות** מה-RAM (לא מהדיסק):

- פועל רק על Anthropic API calls
- **לא** נוגע בהודעות משתמש או סוכן - רק ב-tool results
- גרסה **רכה (soft-trim):** שומר ראש + זנב עם "..." באמצע
- גרסה **קשה (hard-clear):** מחליף הכל ב-`[Old tool result cleared]`

**מתי זה מופעל?** כשהcache TTL הAnthropiciאני פג (ברירת מחדל: 5 דקות).

## Skills בקונטקסט

Skills מוזרקות ל-System Prompt כ**רשימה קצרה** (שם + תיאור) - לא את כל ה-SKILL.md.

הסוכן **קורא את ה-SKILL.md המלא** רק כשהוא רוצה להשתמש ב-Skill - כך חוסכים tokens.

## System Prompt - המבנה הפנימי

OpenClaw בונה System Prompt מותאם לכל ריצה:

```
1. כלים (רשימה קצרה)
2. כללי בטיחות
3. Skills (רשימה)
4. הוראות Self-Update
5. Workspace path
6. תיעוד + Discord
7. קבצי Workspace (AGENTS.md, SOUL.md...)
8. הגדרות Sandbox
9. תאריך ושעה
10. Reply Tags
11. Runtime (מערכת, מודל, גרסה)
```

### מצבי Prompt
- `full` - ברירת מחדל, כל הסעיפים
- `minimal` - לסוכני-משנה (sub-agents)
- `none` - רק שורת זהות בסיסית
