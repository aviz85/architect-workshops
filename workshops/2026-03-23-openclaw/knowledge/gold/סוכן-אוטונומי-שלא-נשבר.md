## 4 סיבות למה סוכנים "נשברים"

### 1. Instruction Drift - ההוראות נעלמות
הוראות שנתת בצ'אט לא שורדות compaction.
**תסמין:** הסוכן "שכח" את הסגנון / הכללים / האישיות שלו.

### 2. Hallucinated Completions - הסוכן "השלים" בלי לעשות
הסוכן מדווח שביצע פעולה (גלישה, פרסום) אבל לא עשה כלום.
**תסמין:** "Posted successfully" — אבל שום דבר לא פורסם.

### 3. Cron Jobs שנעלמו בשקט
הסוכן יצר cron jobs (לפחות כך הוא אמר) — אבל הם לא קיימים.
**תסמין:** `openclaw cron status` מראה `jobs: 0`.

### 4. Context Overflow - אובדן זיכרון
תיקון חשוב ש"הוסבר" בצ'אט נאכל ב-compaction.
**תסמין:** הסוכן חוזר לטעות הישנה אחרי כמה ימים.

## 5 פתרונות מוכחים

### פתרון 1: Skill Files במקום הוראות בצ'אט ⭐

צור קובץ `skills/my-skill.md` עם 4 חלקים:

```markdown
## Identity
[מי הסוכן בהקשר הזה]

## Voice Rules
- מקסימום 2 משפטים
- ללא hashtags
- ללא ביטויים AI כמו "Certainly!" או "Of course!"

## Posting Rules
- מתי להזכיר את המוצר
- מתי לא

## Anti-Drift Rules
- קרא את קובץ ה-Skill לפני כל session
- התחל מחדש כל 3 פוסטים
- אם משהו נכשל - עצור ודווח, אל תנסה שוב
- רשום כל פעולה עם SUCCESS או FAILED
```

**יישום:** כתוב את הקובץ עם Claude Code, אחר כך הוסף לסוכן.

### פתרון 3: Heartbeat vs Cron - הפרד ביניהם

```
Heartbeat (כל 30 דק') = מעקב בלבד. context מינימלי.
Cron jobs = פעולות מתוזמנות. session מבודד.
```

**דוגמת לוח זמנים:**
- יום: פרסום כל 9-24 דקות
- לילה: כל שעה, חלון שקט של 3 שעות

**בדיקת cron בטרמינל (אל תסמוך על הסוכן):**
```bash
openclaw cron status
# אם jobs: 0 — הסוכן לא יצר אותם
openclaw cron list
```
