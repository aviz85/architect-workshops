## המציאות הבסיסית

> "OpenClaw isn't secure by default—security is your responsibility, just as driving safety is the driver's responsibility, not the car's."

OpenClaw יכול להריץ פקודות shell, לקרוא קבצים, ולבצע scripts על המחשב שלך.
אם מוגדר בצורה לא נכונה → **backdoor**.

## 4 סיכוני האבטחה העיקריים

### 1. Misconfiguration Exposure
- Agent שנשאר נגיש על IP ציבורי ללא auth
- Credentials גנובים שנותנים לתוקף גישה בעלת הרשאות גבוהות
- דוקומנטציה: מקרים ידועים של exploit ב-domains ישנים (redirects לmalware)

### 2. Prompt Injection
- קלט זדוני מוסווה כנתונים לגיטימיים
- **דוגמה**: מייל שמכיל הוראות נסתרות לexfiltrate קבצים
- **הגנה**: input validation, LLM safety training, capability sandboxing
- **כלל**: התייחס לכל תוכן חיצוני (מיילים, web pages, calendar entries) כ-**potentially hostile**

### 3. Accuracy Failures
- נתונים מהוזים או הוראות שפורשו בצורה שגויה
- **הבעיה**: לולאות אוטונומיות מגדילות שגיאות קטנות (מוחקות קבצים לא נכונים, שולחות מיילים לא נכונים)
- **הגנה**: human oversight, approval workflows, logging מקיף

### 4. Plain Text Credentials
- API keys ו-tokens מאוחסנים ללא הצפנה כברירת מחדל
- פריצה לשרת = אובדן גישה מלאה
- **פתרון**: Doppler לניהול secrets, NEVER hardcode

## Checklist: Hardening מינימלי לפני שימוש

**רמה בסיסית (חובה)**:
- [ ] הפעל OpenClaw ב-VPS נפרד, לא על המחשב האישי
- [ ] Run: `openclaw doctor --fix`
- [ ] וידא localhost-only binding (127.0.0.1:18789)
- [ ] נעל הרשאות לתיקיית config
- [ ] Tailscale VPN + SSH enabled, חסום inbound traffic
- [ ] Git-track את `~/.openclaw` עם .gitignore נכון

**רמה מתקדמת (מומלץ)**:
- [ ] Firewall: חסום הכל מלבד Tailscale
- [ ] Authentication token (חובה אם נגיש מרשת)
- [ ] Activity logging ו-audit trails
- [ ] Rate limiting על API calls ופקודות
- [ ] Approval gates לפעולות high-risk
- [ ] Weekly review של agent permissions

**אינטגרציות**:
- [ ] מייל נפרד ייעודי לסוכן (לא המייל האישי)
- [ ] Burner phone לWhatsApp integration
- [ ] Read-only API tokens כשאפשר
- [ ] חשבונות שירות ייעודיים עם הרשאות מוגבלות
- [ ] 2FA על כל שירות מחובר

## Simon Roses' Security Implementation (דוגמה ריאלית)

**מה הוא הגדיר**:
1. **Sandboxed execution**: גישת filesystem מוגבלת לתיקיית workspace בלבד
2. **Explicit exec approvals**: עצור לפקודות מסוכנות כמו `rm -rf`
3. **Read-only production access**: יכול לקרוא לוגים, לא יכול לpush ל-main
4. **Audit logging**: כל הפקודות לוגיים לreview שבועי
5. **App-specific passwords**: לא הסיסמה הראשית
6. **SSL/TLS**: ports 993/465 לאימייל

## Troubleshooting שנלמד בדרך הקשה

| בעיה | סיבה | פתרון |
|------|------|-------|
| Message duplication | שני channels פעילים בו-זמנית | הגדר channel priority routing |
| Gmail account banned | זיהה יצירה פרוגרמטית | עבור לדומיין מקצועי |
| Memory overflow אחרי 3 ימים | Context window מלא | הפעל automatic memory compaction ב-800k tokens |
| Docker permission errors | User לא ב-docker group | הוסף user לgroup, restart gateway |
| Telegram rate limiting | עונה לכל heartbeat | הגדר heartbeat ל-silent mode |
| API limits שוברים בשקט | לא מגיעה הודעת שגיאה | הגדר billing alerts |

## הCISSP Mindset לOpenClaw

> "I thought of it running with any kind of exposure...with my Apple ID was terrifying." — Hacker News user

**הגישה הנכונה**: הסוכן הוא **trusted employee** עם גישה גבוהה.
תתייחס אליו כמו שמתייחסים לemployee עם מפתחות לכל המשרד:
- ידיעה ברורה מה הוא יכול לעשות
- logging של כל הפעולות
- review תקופתי
- הגבלות ברורות על מה לא מורשה
