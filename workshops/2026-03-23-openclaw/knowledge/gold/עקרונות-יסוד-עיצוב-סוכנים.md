## עיקרון 1: ספציפיות = ביצועים

> "The specificity of SOUL.md directly correlates with agent performance."

**חלש**: "You are a helpful AI assistant."
**חזק**: "You are a Senior DevOps engineer with 12+ years in AWS, Kubernetes, CI/CD. Personality: calm pragmatism. You find elegant solutions and get slightly annoyed by over-engineering."

**ממד אחרי ממד** — כל דבר שלא מוגדר, הסוכן ממציא. תמיד מגדיר: טון, עומק, format העדפות, עקרונות החלטה.

---

## עיקרון 2: Boot Sequence = פתרון ל-Agent Amnesia

**הבעיה**: ללא boot sequence, סוכנים סובלים מ-amnesia — מתעוררים חדשים בכל session.

**הפתרון ב-AGENTS.md**:
```
1. Read SOUL.md          → מי אני
2. Read USER.md          → מי אני עוזר לו
3. Load self-improvement skill → enable reflection
4. Read today's memory file  → recent context
5. Check long-term memory    → accumulated knowledge
```

**ה-BOOTSTRAP.md pattern**: קובץ אחד שאומר לסוכן "תגלה מי אתה" → אחרי שהבין, מחק את הקובץ.
`"If BOOTSTRAP.md exists, that's your birth certificate. Follow it, figure out who you are, then delete it."`

## עיקרון 3: Multi-Agent Specialization (לא one-size-fits-all)

**Pattern 1: Hierarchical Delegation**
```
Project Manager Agent
    ├── Research Lead Agent
    │   └── Research Sub-Agents (x3)
    ├── Dev Lead Agent
    │   └── Dev Sub-Agents (x5)
    └── Marketing Lead Agent
        └── Content Agents (x4)
```
תוצאות זורמות חזרה למעלה. Scalability אמיתית.

**Pattern 2: Functional Specialization**
| Agent | תפקיד | Authorization |
|-------|--------|---------------|
| PR-Reviewer | Code review | Level 2 - propose & execute |
| Issue-Triager | Classify priorities | Level 3 - full autonomy |
| CodeMod | Bulk refactoring | Level 2 - create PRs |
| Dependency-Auditor | Security updates | Level 3 for patches, escalate majors |
| CI-Monitor | Build pipelines | Level 3 - retry authority |

**למה ספציאליזציה עובדת**:
> "One all-purpose agent becomes unstable. Multiple agents with clear responsibilities reduce errors because each focuses on a narrow task."

## עיקרון 4: Dynamic Sub-Agent Spawning

לטאסקים מורכבים — יצור sub-agents מקביל:
```
Research Agent receives: "Analyze 5 market segments"
    ↓ spawns 5 parallel sub-agents (one per segment)
    ↓ waits for all results
    ↓ synthesizes
```
**תוצאה**: 5x מהר יותר.

**מימוש**: `Single-gateway multi-agent` = תקשורת מהירה בתוך process via `sessions_send()`. `Multi-gateway fleet` = agents מבודדים על מכונות שונות.

## עיקרון 5: Self-Improving Agents

> "Enable self-improvement: compounding benefits over weeks."

**המנגנון**: אחרי כל task, הסוכן:
1. מעריך את הפלט שלו
2. רושם לקחים ב-long-term memory
3. משפר את הביצוע הבא

**מיקום הלמידה**: `~/self-improving/agents/<name>/` — permanent files.

## עיקרון 6: SOUL.md Structure — 5 עמודות

```markdown
## Identity
[Role, personality, background, quirks]

## Communication Style
[Tone, format, depth, initiative level]

## Domain Knowledge
[Tech stack, preferences, coding standards]

## Decision Framework
["Security > convenience, always"
 "Prefer boring technology"
 "Make it work first, optimize later"]

## Hard Boundaries
[What the agent will NEVER do without explicit approval]
```

**גבולות נוקשים מומלצים**:
- ❌ `rm -rf` ללא אישור
- ❌ `DROP TABLE` ללא אישור
- ❌ commits ישירים ל-main
- ❌ שליחת אימייל חיצוני ללא approval
- ✅ Trash > Delete (תמיד reversible)

## עיקרון 7: Rules עם Personas

**Marcus Reid Pattern (3 Personas)**:
- **Morty** (Sidekick): אצירת תוכן, גילוי כלים, הנאה
- **Pepper Potts** (Chief of Staff): ניהול עסקי, תקשורת, משימות
- **David Goggins** (Coach): accountability, כושר, check-ins

**למה לחלק לפי persona ולא לפי task**:
כשה-agent מגיע לשיחה עם "אישיות" ברורה, ה-quality של התגובות משתפר. הסוכן "מבין" מה מצופה ממנו.

---

## עיקרון 8: Clear Authority Levels

כל sub-agent צריך **authority boundary** מפורש:
- **Level 2**: מציע ומבצע, אבל יוצר PR/draft לreview
- **Level 3**: אוטונומיה מלאה בתוך קריטריונים מוגדרים
- **Escalation**: מתי לשאול אנושי

**Sub-agents inherit parent context** — אבל פועלים עם boundaries מוגדרים משלהם ב-`AGENTS.md`.

## עיקרון 9: Version Control הכל

```bash
# Git + GNU Stow pattern
~/.openclaw/agents/ → symlinks to → ~/dotfiles/openclaw-config/
```

**למה זה קריטי**:
- Disaster recovery: 10 דקות → `clone repo, run stow, restart`
- Track changes בזמן
- Deploy אותו config לmachines שונות
- Review שינויים לפני deploy

## עיקרון 10: Determinism > LLM לtasks קבועים

**Pattern חשוב מ-production**:
```
Email monitoring כל 15 דקות:
  ❌ LLM heartbeat שמחליט מה דחוף → יקר, לא אמין, context-dependent
  ✅ cron + shell script → deterministic filtering
     → רק כשנמצאו items דחופים → אז קרא ל-LLM
```

> "Let LLMs handle judgment and language generation. Let scripts handle structured computation and scheduling."

## Patterns נפוצים מ-Production

### Morning Standup Automation (DevBot pattern)
```
6 AM:
1. spawn Issue-Triager → process yesterday's issues
2. spawn Dependency-Auditor → check security advisories
3. collect PR-Reviewer drafts
4. query CI-Monitor results
5. send consolidated digest to human
```
**תוצאה**: אדם מתחיל יום ב-"מה טופל", "מה דורש תשומת לב", "מה escalated".

### Content Pipeline (Media company)
```
Daily AI news collection → Auto summarization → Draft articles → WordPress upload → Editor review alert
```
שמירת editorial control תוך ביטול עבודת עיבוד נתונים חוזרת.

### STATE.yaml Coordination
```yaml
# Shared state between 3-5 agents
project: "landing-page-redesign"
status: "in-progress"
assigned_to: "dev-agent-2"
last_updated: "2026-03-24T10:30:00"
review_needed: true
```
תיאום multi-agent ללא orchestration מורכב.
