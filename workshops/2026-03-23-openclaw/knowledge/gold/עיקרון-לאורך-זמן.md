הוסף את הסוכן לקבוצות עם אנשים מהימנים.

## מה קורה עם Context ועלויות אחרי שבועות

### הבעיה: 3 בעיות מצטברות

**1. Context Bloat (נפיחות הקשר)**
> "By week three, the memory graph has grown, the search results are broader, and the conversation history from your previous sessions is traveling with every new request."

כל request כבר מתחיל עם load כבד: SOUL.md + AGENTS.md + bootstrap + memory searches.
הסוכן טוען **הכל** במקום לאחזר selevctively מה שרלוונטי.

**2. Static Content Reprocessing (עיבוד חוזר של תוכן סטטי)**
הוראות system, bootstrap files, תצורת agent - **לא משתנות** משבוע לשבוע.
אבל מעובדות מחדש מאפס בכל request, ללא caching.
Heartbeat של 30 דקות = API calls רצופים שמעבדים content זהה.
**תוצאה**: עלויות שמצטברות בשקט עד שהחשבון מגיע.

**3. Uniform Model Routing (routing אחיד לכל הבקשות)**
> "OpenClaw routes all requests to a single globally configured model regardless of task complexity."
בדיקת סטטוס, memory lookup, formatting, reasoning - כולם מגיעים לאותו endpoint יקר.
רוב העבודה היומיומית = פעולות פשוטות שלא צריכות frontier model.

### הפתרון: Manifest Plugin

Intelligent routing שמיירט requests לפני קריאת המודל.
**23 ממדים** להערכת כל request:
- 13 keyword checks: "prove", "write function", "what is"
- 10 structural checks: token count, nesting depth, code-to-prose ratio

**4 שכבות מודל**:
- **Simple**: ברכות, הגדרות, עובדות → מודלים הכי זולים
- **Standard**: עזרה בקוד, שאלות בינוניות → איכות טובה/עלות נמוכה
- **Complex**: tasks רב-שלביות, context גדול → מודלים הכי טובים
- **Reasoning**: לוגיקה פורמלית, הוכחות, מתמטיקה → מסוגלי reasoning בלבד

**תוצאה**: "up to 70% cost reduction"

## תבנית ה-Rotating Heartbeat

**הבעיה**: כל heartbeat מריץ הכל - אימייל, לוח שנה, git, tasks בו-זמנית.
**הפתרון**: קבץ בדיקות ובצע את הבדיקה שהכי מאוחרת בכל מחזור.

```json
// heartbeat-state.json
{
  "checks": {
    "email": "last_run",
    "calendar": "last_run",
    "tasks": "last_run",
    "git": "last_run"
  }
}
```
כל heartbeat: מה הכי ישן? בצע אותו. עדכן.

### אחרי חודש: מה עבד, מה נשבר (One Month Later)

**Use case שפרץ כמוביל (Multi-agent STATE.yaml)**:
- 3-5 agents מתאמים דרך shared state files
- פיתחו, בדקו, ותיעדו קוד — ללא מנהל
- "Autonomous project teams work"

**Meeting Processing Pipeline** — use case הכי-אדוקד:
- Agents transcribe recordings + extract action items + sync to project management
- Cloud services (RunTheAgent) batch-process recordings יומיים ל-Slack summaries
- ללא מעורבות מנהל

**Morning Briefings** — use case הכי-popular:
- Weather + calendar + email + tasks
- Advanced: health data + GitHub Trending + Hacker News
- מחליף multiple newsletter subscriptions

**Model Routing** — חיסכון 60-80%:
- "Router agents" מפיצים לפי מורכבות
- Simple → Gemini Flash | Complex → Claude Opus
- "Community reports: 60-80% API cost reduction without quality loss"

### 4 שבועות ב-Production: שינוי חשיבה

**שבוע 1**: Setup + chaos. Configuration = messy.
**שבוע 2**: Scale ceiling נפגש (single server). Optimization כבר נדרש.
**שבוע 3**: Memory files מצטברים. Daily logs בסדר עדיין.
**שבוע 4**: Git-tracked config = disaster recovery בדקות.

**Shift מנטלי קריטי**:
```
מ: prompt-based (להסביר preferences כל פעם)
ל: configuration-based (JSON configs, version-controlled)

מ: transaction logs (כל פעולה)
ל: operational memory (החלטות, relationships, commitments)

מ: heartbeats כ-LLM periodic tasks
ל: cron jobs (deterministic) + LLM רק לjudgment
```

### Disaster Recovery: Git + Stow Pattern

```bash
# Setup פעם אחת:
mkdir ~/dotfiles/openclaw-config
cd ~/dotfiles/openclaw-config
git init && git remote add origin git@github.com:...
stow --target=~/.openclaw/agents/ .

# Recovery (כל מצב):
git clone ... && stow . && openclaw restart
# זמן: 10 דקות
```

**לפני**: שחזור agent = ימים של reconfiguration
**אחרי**: 10 דקות
