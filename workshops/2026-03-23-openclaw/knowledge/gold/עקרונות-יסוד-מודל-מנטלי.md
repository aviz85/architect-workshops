## המודל המנטלי הבסיסי: שרות תמידי, לא אפליקציה

> "OpenClaw is an ambient service, not an app. You don't invoke it — you converse with it."

**Claude Code** = כלי שמופעל on-demand, לפי session
**OpenClaw** = שרות שרץ תמיד, גם בזמן שאתה ישן

זה השינוי הגדול ביותר בחשיבה. OpenClaw לא "עוזר לך לבצע". הוא קיים ופועל כל הזמן.

---

## ה"מנהל-על": הטרנספורמציה המרכזית

**מהצלחת לנכשל (Executor → Super Individual)**:
לפני: כתבת קוד, בדקת, ניפית. AI רק עזר לתהליך.
→ נשארת executor עם AI כלי

**הגישה הנכונה (Manager → Super Manager)**:
> "A manager shouldn't get bogged down in the specifics — they should focus on the higher-level, abstract work."
> "True management happens when you accomplish goals purely through communication."

הביצוע עצמו מואצל לסוכנים. אתה רק מנחה ומכוון.

**המימוש**: "I just need to express my intent, and it automatically creates the project, writes up a plan for me to review."

## ארכיטקטורת 4 הרכיבים

```
Gateway (כניסת הודעות מ-Telegram/WhatsApp/Slack)
    ↓
Agent (reasoning - LLM)
    ↓
Skills (פעולות בעולם האמיתי)
    ↓
Memory (זיכרון מתמשך)
```

**תובנת חומרה**: "Heavy computation happens remotely on your model provider's servers. Your machine is merely the conductor."
VPS של €5/חודש עם 2 vCPU ו-4GB RAM מספיק לחלוטין. CPU שהות ב-3-5%.
**Mac Mini = מיתוס**. אין צורך בחומרה מקומית.

## Markdown-as-Config: הפילוסופיה

> "Agents are configured through plain-text files managed by a persistent Gateway daemon."

כל הגדרת ה-agent = קבצי Markdown. לא Python, לא גרפים, לא קוד.
- ניתן לעריכה בכל editor
- גרסאות ב-Git
- grep וחיפוש
- backup פשוט

זה לא רק נוחות — זו הגדרה עמוקה: **agent כ-plain-text operating system**.

---

## הפרדת זהות מתשתית

OpenClaw מפריד בין:
- **Agent identity** (role, behavior, personality) — קבצי Markdown
- **Agent infrastructure** (tool orchestration, memory, channel routing) — Gateway daemon

למה זה חשוב: אפשר לשנות את ה"מי" בלי לגעת ב"איך".

## Workspace-First Philosophy

מקור האמת = קבצי תצורה. לא ה-session, לא ה-chat history.

```
SOUL.md    → Purpose & behavior definition
TOOLS.md   → Capability specification
IDENTITY.md → Personalization settings
HEARTBEAT.md → Execution configuration
AGENTS.md  → Boot & operational protocols
USER.md    → Context about the human
MEMORY.md  → Accumulated long-term knowledge
```

**מה ששורד compaction**: רק מה שכתוב לקבצים. שיחות — נמחקות.

---

## The Perceive-Decide-Act Loop

הבסיס הפילוסופי:
1. **Perception** — חישה סביבתית (הודעות, API calls, web search, קבצים)
2. **Decision** — inference על פי context + files + memory
3. **Action** — ביצוע דרך skills

**שוני מתוכנה רגילה**: Software מבצע נתיב קבוע מראש. Agent קובל מטרה ומחליט איך להגיע אליה.

---

## ספקטרום האוטונומיה (0-5)

| רמה | תיאור | מתי להשתמש |
|-----|--------|------------|
| 0 | Human does everything | Learning phase |
| 1 | AI suggests, human decides | High-stakes domains |
| 2 | AI proposes + executes with review | Most workflows |
| 3 | AI full autonomy within criteria | Routine tasks |
| 4-5 | Full autonomy | Only after proven trust |

**מסקנת production**: מערכות עובדות טוב ברמות 2-3. לא מקסימום אוטונומיה.

---

## The Conversation Interface Scales Differently

> "You don't interact with eight separate tools; you converse with one intermediary that coordinates them. This scales better than traditional integrations."

במקום: ניהול 8 אינטגרציות נפרדות, 8 dashboards, 8 לוגיקות
עם OpenClaw: שיחה אחת שמנהלת הכל

**אפקט ה-super manager**: עצם ממשק השיחה מאפשר ניהול של מערכת מורכבת שמאחוריה.

---

## מה OpenClaw לא עושה (טעות נפוצה)

**לא** מחליף Claude Code — הם משלימים
**לא** מאחסן AI בעצמו — רק מנהל שיחות ל-providers
**לא** מייצר LLM מקומי — conductor לחישוב בענן
**לא** מוצר לצרכן — framework שאתה מגדיר לתוך מוצר
