## 4 שכבות הזיכרון — המפה המלאה

```
Layer 1: Bootstrap Files
  (SOUL.md, AGENTS.md, USER.md, MEMORY.md, TOOLS.md)
  → נטענים מחדש בכל session מ-disk
  → שורדים כל compaction
  → ALWAYS present

Layer 2: Session Transcript
  → שיחה נשמרת כ-JSONL ב-disk
  → עלולה לעבור compaction כשcontext מתמלא
  → lossy (compression מאבד פרטים)

Layer 3: LLM Context Window
  → 200K tokens — הכל מתחרה כאן
  → compaction triggered כשמתמלא
  → fixed capacity

Layer 4: Retrieval Index
  → Vector + keyword search
  → memory_search + memory_get tools
  → on-demand access
```

## 3 מצבי כישלון (הנפוצים ביותר)

**Failure A (הנפוץ ביותר)**:
מידע קיים רק בשיחה, לא נכתב לקבצים.
נמחק ב-compaction או session reset.
→ **Fix**: אמור לסוכן "כתוב זאת ל-MEMORY.md"

**Failure B**:
Compaction יוצר summaries עם loss of nuance — פרטים ספציפיים נזרקים.
→ **Fix**: `reserveTokensFloor: 40000` = מספיק מקום לפני compaction

**Failure C**:
Session pruning חותך tool results בזיכרון — אבל on-disk records שלמים.
→ **Fix**: כמעט אוטומטי — הon-disk לא נפגע

---

## הכלל הגדול

> **"If it's not written to a file, it doesn't exist."**

Instructions בשיחה → נעלמות אחרי compaction.
"זכור שאני מעדיף X" בשיחה → נזרק.
"כתוב ל-MEMORY.md שאני מעדיף X" → קיים לעד.

---

## Compaction vs. Pruning — ההבדל

| | Compaction | Pruning |
|--|------------|---------|
| **מה קורה** | שכתוב מחדש של history | חיתוך tool results |
| **השפעה** | קבועה — rewrites history | זמנית — per-request |
| **On-disk** | נשמר קיים | לא נפגע |
| **מה נאבד** | nuance ופרטים ספציפיים | tool outputs (זמנית) |
| **מניעה** | reserveTokensFloor, /compact proactive | אוטומטי |

## 3-Layer Defense Strategy

### שכבה 1: Pre-Compaction Memory Flush
```yaml
# בconfig של OpenClaw:
reserveTokensFloor: 40000
```
נותן לסוכן headroom לכתוב לffiles לפני compaction אוטומטי.

### שכבה 2: Manual Memory Discipline
- לפני החלפת נושא: "save this to MEMORY.md"
- `/compact` proactively — אל תחכה לoverflow
- אחרי `/compact` יש maximum runway ב-fresh context

### שכבה 3: File Architecture
```
Bootstrap files → נטענים בכל turn (שורדים הכל)
Daily logs → memory/YYYY-MM-DD.md (accessible via search)
MEMORY.md → loaded directly in direct sessions
```

**חשוב**: Run `/context list` לוודא MEMORY.md נטען ולא truncated.
Memory files מעל 20,000 תווים = נחתכים בשקט.

## QMD — Quality Memory Digest (פתרון לlong-term)

**הבעיה (חודש 2-6)**:
```
חודש 1: 30 daily log files
חודש 2: 60 files → memory_search מאט
חודש 3: 90 files → timeout
חודש 6: 180 files → "לא יכול למצוא תקציב מ-2 שבועות"
```

**הפתרון**:
```
שמור: current week כdaily logs (active)
קומפרס: שבוע ישן → digest קצר
Archive: transaction logs (routine operations) בנפרד

חודש 6 = 26 QMD + current week (לא 180 קבצים)
```

**מה לשמור ב-digest**: החלטות, התחייבויות, שינויי pattern (5% מהלוג)
**מה לarchiive**: "sent email", "checked calendar", "completed X" (90% רעש)

## Model Tiering — חיסכון 60-80%

**Manifest Plugin (23 dimensions)**:
- 13 keyword checks: "prove", "write function", "what is"
- 10 structural checks: token count, nesting depth, code-to-prose ratio

**4 שכבות מחיר**:
| Tier | משימות | מודל |
|------|--------|------|
| Simple | ברכות, הגדרות, עובדות | Gemini Flash, Haiku |
| Standard | עזרת קוד, שאלות בינוניות | Claude Sonnet, GPT-4o-mini |
| Complex | multi-step, large context | Claude Sonnet |
| Reasoning | לוגיקה, מתמטיקה, הוכחות | Claude Opus, o3 |

**תוצאה**: "up to 70% cost reduction" — מ-$160+/חודש ל-$45-50 לשימוש כבד.

**Cost Rule of Thumb**: בדיקת heartbeat + routing + simple tasks = cheap models. Creative + complex = premium models.

## Context Limits — המספרים

```
Per-file limit: 20,000 characters
Aggregate cap: 150,000 characters (all bootstrap files)
Context window total: 200,000 tokens
reserveTokensFloor recommended: 40,000
```

**מה לבדוק**:
```bash
/context list  # verify MEMORY.md loaded
/context size  # how much is used
```

## Memory Protocol Rules (Best Practice)

```markdown
## Before answering questions about past work:
→ search memory first (memory_search)

## Before starting new tasks:
→ check today's memory file for context

## When learning something important:
→ write to MEMORY.md immediately

## When corrected by user:
→ add correction as rule to MEMORY.md

## At end of session:
→ summarize to daily log
→ promote key insights to MEMORY.md
```

## Track A vs. Track B — שיטות Retrieval

**Track A (Built-in)**: Local hybrid search
- Keyword matching + embedding-based semantic search
- על MEMORY.md + memory directory
- אין setup חיצוני

**Track B (QMD/Advanced)**: Extended backend
- Obsidian vaults, project docs, meeting notes
- Past session transcripts מחוץ ל-workspace
- Multilingual support (768-dim embeddings)
- 7ms GPU latency (advanced setups)
