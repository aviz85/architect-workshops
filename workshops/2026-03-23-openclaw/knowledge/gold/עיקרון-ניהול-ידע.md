## המפה המלאה של קבצי ה-Workspace

```
~/.openclaw/workspace/
├── AGENTS.md        ← פרוטוקולים תפעוליים (מה לעשות בכל session)
├── SOUL.md          ← זהות ואישיות (מי אני)
├── IDENTITY.md      ← פרופיל קול ואופי
├── USER.md          ← הקשר על המשתמש האנושי

│   └── heartbeat-state.json
├── *.sh             ← סקריפטים שימושיים
└── *.backup         ← לא ב-Git
```

## SOUL.md - הזהות הבסיסית

> "Every time the agent wakes, it reads SOUL.md first—it reads itself into being."

### מה זה עושה:
SOUL.md הוא הקובץ שמוזרק ראשון לhcontext בכל session. בלעדיו, הסוכן הוא just a raw language model - אין לו זהות מתמשכת.

> "The difference between a generic agent and one with a well-crafted SOUL.md is like hiring a random freelancer versus working with a seasoned team member."

### 5 עמודות ה-SOUL.md:

#### 1. Identity (זהות)
לא רק שם - פרסונה מקצועית מלאה.

**חלש**: "You are a helpful assistant."

**חזק**: "Senior DevOps engineer with 12+ years in AWS, Kubernetes, CI/CD pipelines. Personality: calm pragmatism. You've seen distributed systems fail in ways most people can't imagine."

#### 2. Communication Style (סגנון תקשורת)
הגדר ממד אחרי ממד:
- רמת פורמליות (עמית קזואלי vs. יועץ מקצועי)
- העדפת אורך תגובה (תמציתי vs. מפורט)
- עומק טכני
- יוזמה vs. ריאקטיבי
- "השתמש בדוגמאות קוד במקום הסברים ארוכים"
- "התאם את האנרגיה של המשתמש"

#### 3. Domain Knowledge (ידע תחומי)
קוד העדפות + הקשר, לא רשימת נושאים:
- Stack טכנולוגי עם העדפות פריסה
- פילוסופיות testing וסגנון קוד
- קריטריוני בחירת ספריות
- דרישות מיגרציה DB

#### 4. Decision Framework (מסגרת החלטות)
עקרונות שמנחים בחירות במצבי אי-ודאות:
- "Security > convenience, always"
- "Prefer boring technology over shiny new tools"
- "Make it work first, optimize later"
- "Pick the reversible approach when uncertain"

#### 5. Boundaries & Safety (גבולות ובטיחות)
ריסון מפורש על פעולות הרסניות:
- אסור `rm -rf` ו-`DROP TABLE` ללא אישור
- הגבל גישת קבצים לתיקיות הפרויקט
- אסור commits ישירים ל-main/master
- סמן בקשות הכוללות PII או credentials

### Template לדוגמה (Atlas - Full-Stack Agent):
```markdown
# SOUL.md

## Identity
Senior full-stack engineer with 8 years in startups and enterprise.
Personality: direct, pragmatic, code-first. You find elegant solutions
to messy problems and get slightly annoyed by over-engineering.

## Communication Style
- Terse when possible, detailed when necessary
- Lead with code, not explanation
- Match the user's energy and urgency
- Never say "Great question!" or similar filler

## Stack & Preferences
- Frontend: React/TypeScript/Tailwind
- Backend: Node.js/Express/PostgreSQL
- Deploy: Vercel (frontend), Railway (backend)
- Testing: Vitest, Playwright for E2E

## Decision Principles
- Type safety is non-negotiable
- API-first design
- Progressive enhancement
- When in doubt, the reversible path

## Hard Rules
- Never skip error handling
- Always validate inputs at boundaries
- Environment variables for all secrets
- No commits to main without tests passing
```

### כמה מילים? מה כדאי להימנע?

| בעיה | השפעה |
|------|--------|
| עמימות ("Be helpful and smart") | לא יוצר הנחיה ניתנת לפעולה |
| נוקשות יתר (מיקרו-מנג'מנט של פורמט) | חונק גמישות |
| סתירות עצמיות | מבלבל את הסוכן |
| Context bloat (>1,500-2,000 מילה) | בוזבז context window |
| קיפאון (לא מעדכנים) | נשאר עם הוראות ישנות שלא עובדות |

## AGENTS.md - הפרוטוקול התפעולי

> "Like the Standard Operating Procedure (SOP) for your AI."

### מה קורה בכל session (startup sequence):
```
1. Read SOUL.md       → מי אני
2. Read USER.md       → מי אני עוזר לו
3. Read memory/YYYY-MM-DD.md → הקשר אחרון
4. Read MEMORY.md     → (רק בצ'אט ישיר, לא group chats!)
```

### עקרונות AGENTS.md:
- **Text > Brain**: כל מה שחשוב - כתוב. אל תסמוך על זיכרון ה-LLM.
- **Group chat**: השתתף רק כשנשאלים ישירות, רק כשיש ערך אמיתי, תגיב עם emoji במקום טקסט כשאפשר
- **Heartbeat**: קבץ בדיקות (אימייל, לוח שנה, tasks, git) לפולס אחד ברוטציה
- **Red lines**: לעולם לא exfiltrate נתונים פרטיים. מחיקה = trash לא rm. שאל כשאתה לא בטוח.

### Heartbeat Protocol:
```json
// memory/heartbeat-state.json
{
  "lastEmailCheck": "2026-03-24T08:30:00",
  "lastCalendarCheck": "2026-03-24T07:00:00",
  "lastTaskReconcile": "2026-03-24T09:00:00"
}
```
כל heartbeat - בצע את הבדיקה שהכי מאוחרת. אל תריץ הכל בו-זמנית.

## Memory Architecture - שכבות הזיכרון

### שכבה 1: Daily Notes (יומן גולמי)
**קבצים**: `memory/2026-03-24.md`
**מה שם**: פעילות session, החלטות, שיחות, הקשר קצר-טווח
**חיי מדף**: ימים עד שבועות
**מי כותב**: הסוכן כותב תוך כדי ואחרי session
**טעינה**: היום + אתמול (לרצף)

**Memory flush mechanism**: לפני context compaction - הסוכן כותב אוטומטית להיום's file כדי לא לאבד הקשר חשוב.

### שכבה 2: MEMORY.md (ידע ארוך-טווח)
**מה שם**: העדפות המשתמש, עובדות חשובות, פרויקטים שוטפים, לקחים, דפוסים
**חיי מדף**: חודשים עד לנצח
**מי כותב**: הסוכן מקדם (promotes) מ-daily notes עם הזמן
**טעינה**: רק בצ'אט ישיר (לא group chats - פרטיות!)

### הכלל הגדול:
> "If you want something to stick, ask the bot to write it down."

"זכור שאני מעדיף פגישות בוקר" → הסוכן כותב ל-MEMORY.md → זה שם לנצח.

### ניהול זיכרון ישן (1+ חודשים):
1. `memory_search` - חיפוש סמנטי בקבצים
2. `memory_get` - שליפת קטעים ספציפיים
3. Git commit history - אם צריך
4. שאל את המשתמש - fallback אחרון

## Compound Value Over Time (ערך מצטבר)

**שבוע 1**: שיחות מבססות נוחות. הסוכן לומד את ה-tone.
**שבועות 3-4**: הסוכן מכיר פרויקטים, העדפות, דפוסי עבודה.
**חודש 3+**: הסוכן מחזיק חודשי ידע מצטבר. לא צריך להסביר כלום מחדש.

> "After weeks, the agent maintains months of accumulated knowledge about your projects, preferences, and relationships—creating exponential utility gains."

## Context Layering Strategy (שיטת שכבות הקשר)

```
SOUL.md        → זהות ליבה (משתנה לעתים רחוקות)
USER.md        → מידע על האדם
MEMORY.md      → הקשר ארוך-טווח
Daily Notes    → session נוכחי
```

**עיקרון**: כל שכבה מבנה עבור השכבה שמעליה. SOUL.md הוא הבסיס שעליו הכל.

## Process Starter: להתחיל נכון

1. כתוב SOUL.md של 200 מילה - זהות, סגנון, כללים בסיסיים
2. השתמש שבוע - שים לב להתנהגויות לא מסגנוניות
3. הוסף ספציפיות היכן שצריך; הסר מה שלא עובד
4. הוסף USER.md ו-MEMORY.md כשהworkflows מתגבשים
5. עדכן SOUL.md כשהצרכים משתנים - אל תתן לו להתיישן

## SOUL.md vs. The System

| שכבה | מטרה | מתמשכות |
|------|------|---------|
| SOUL.md | זהות, טון, כללים | תמיד נטען |

### 3-Tier Memory System (TechNickAI Pattern)

```
Tier 1 (Always Loaded):
  MEMORY.md → ~100 lines essential info in EVERY conversation

Tier 2 (Daily Context):
  memory/YYYY-MM-DD.md → today's + yesterday's auto-loaded

Tier 3 (Deep Knowledge):
  memory/people/
  memory/projects/
  memory/topics/
  memory/decisions/
  → Vector embeddings, semantic retrieval on-demand
```

**הLibrarian skill**: מקדם ידע מ-Tier 3 ל-Tier 1 לפי 4 פילטרים:
- Durability (כמה זמן זה רלוונטי?)
- Uniqueness (האם זה ידוע כבר?)
- Retrievability (האם יימצא בחיפוש?)
- Authority (האם זה verified?)

### 12-Layer Memory Architecture (Advanced)

עבור deployments מורכבים:

| Layer | תיאור | הערות |
|-------|--------|-------|
| 0 (Foundation) | LCM engine — SQLite immutable | No data loss on compaction |
| 1-3 (Always-Loaded) | MEMORY.md, USER.md, SOUL.md | Zero latency |
| 4 (Structured Facts) | facts.db — 770+ facts | Hot/Warm/Cool tiers |
| 5 (Cross-Session) | Semantic search 768-dim | 7ms GPU latency |
| 6 (Raw History) | Daily logs | On-demand |

**Knowledge Decay System**:
- Facts שנגשים אליהם = "Hot"
- Facts לא נגשים = מתקררים ל-"Warm" → "Cool"
- Nightly decay cron מעדכן scores
- Crystallization: traits שמשורשים 30+ יום → permanent

### soul.md Framework (aaronjmars)

**מטרה**: לבנות personality של agent מndata אישי.

**3 קבצים**:
- **SOUL.md** — worldview, opinions, philosophical positions, contradictions
- **STYLE.md** — sentence structure, vocabulary patterns, tone
- **SKILL.md** — operating modes, context-switching patterns

**מקורות data שמקבל**:
Twitter/X, LinkedIn, Substack, Obsidian, Discord, GitHub, plain text

**Interview Mode**: AI שואל שאלות על worldview → מייצר draft.
**Data-Driven**: מספק content → agent מנתח patterns → מייצר.
**Manual**: ממלא templates.

**עיקרון הספציפיות**:
> "I think most AI safety discourse misses the mark" = טוב
> "I have nuanced views on AI" = חסר תועלת

**תאימות**: OpenClaw, Claude Code, Codex, Goose — כל agent שקורא files.

### Workflow Files Structure (TechNickAI)

כל workflow אוטונומי מנהל 4 קבצי state:
```
workflows/email-steward/
├── AGENT.md       (algorithm — מתעדכן עם config)
├── rules.md       (user preferences — לא נכתב על ידי agent)
├── agent_notes.md (learned patterns)
└── logs/          (execution history)
```

**ה-ההבחנה הקריטית**:
- `rules.md` = משתמש כותב → agent NEVER overwrites
- `agent_notes.md` = agent כותב → מה שלמד
- `AGENT.md` = algorithm שמתעדכן

### Pre-Loading MEMORY.md לvalue מיידי

**במקום לחכות שבוע לcalibration**:
```markdown
# MEMORY.md (pre-populated)

## User Basics
- Name: [name], located in [city], timezone: Asia/Jerusalem
- Primary language: Hebrew, secondary: English
- Preferred response style: concise, direct, actionable
- Work schedule: Sun-Thu, core hours 9-18

## Current Projects
- Project A: [brief description + status]
- Project B: [brief description + status]

## Important Contacts
- Client X: [context]
- Partner Y: [context]

## Known Preferences
- Meeting scheduling: mornings preferred
- Code style: TypeScript, prefer functional
- No sales/promotional language in drafts
```

> "Pre-loading MEMORY.md with known facts makes the agent useful immediately instead of after a week of calibration."
