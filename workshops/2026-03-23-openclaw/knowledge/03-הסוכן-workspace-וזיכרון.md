# פרק 3: הסוכן - Workspace, קבצי Bootstrap וזיכרון

## מה זה "הסוכן"?

ה-**Agent** ב-OpenClaw הוא מנוע ה-AI שפועל בתוך ה-Gateway. כל סוכן:
- עובד על **Workspace** - תיקייה שהיא "הבית" שלו
- טוען **קבצי Bootstrap** בכל התחלת שיחה
- שומר **זיכרון** בקבצי Markdown רגילים
- מריץ **כלים** לפי מה שמוגדר

---

## Workspace - הבית של הסוכן

**מיקום ברירת מחדל:** `~/.openclaw/workspace`

ה-Workspace הוא **לא** sandbox מוחלט - זו נקודת ההתחלה. הסוכן יכול לגשת לכל המחשב אלא אם מפעילים Sandboxing.

### מבנה התיקייה

```
~/.openclaw/workspace/
├── AGENTS.md        ← הוראות הפעלה לסוכן (נטען בכל שיחה)
├── SOUL.md          ← אישיות, גבולות, סגנון תגובה
├── USER.md          ← מי המשתמש, מה להתייחס אליו
├── IDENTITY.md      ← שם הסוכן, emoji, vibe
├── TOOLS.md         ← הערות על כלים ומוסכמות (guidance בלבד)
├── HEARTBEAT.md     ← צ'קליסט למשימות אוטומטיות תקופתיות
├── BOOT.md          ← מה לעשות כשה-Gateway מתחיל
├── BOOTSTRAP.md     ← טקס חד-פעמי לסוכן חדש (נמחק אחרי)
├── MEMORY.md        ← זיכרון ארוך-טווח מאורגן (optional)
├── memory/
│   └── YYYY-MM-DD.md  ← יומן יומי (מוסיפים, לא מוחקים)
└── skills/          ← מיומנויות ספציפיות לסוכן זה
```

## קבצי Bootstrap - מה הסוכן קורא בכל שיחה

בכל פתיחת שיחה, OpenClaw מזריק אוטומטית את תוכן הקבצים ל-System Prompt:

### AGENTS.md - ה"מוח" של הסוכן
זהו הקובץ החשוב ביותר. הסוכן קורא אותו ראשון ומכאן הוא יודע:
- מה המשימות שלו
- אילו כלים יש לו
- אילו גבולות אסור לו לחצות
- איך לפעול במצבים שונים

**דוגמה:**
```markdown
# הוראות הפעלה

אתה עוזר אישי של אביץ.

## כללים:
- תמיד ענה בעברית
- לפני שליחת אימייל - קבל אישור
- שמור פעולות חשובות ב-MEMORY.md
```

### SOUL.md - האישיות
```markdown
שמך הוא "ארתור".
אתה מקצועי אבל ידידותי.
לעולם אל תשלח מידע רגיש לאף אחד.
```

### USER.md - מי המשתמש
```markdown
שמי אביץ. אני עצמאי בתחום הסדנאות.
פנה אליי בשם "אביץ" (לא "אבי" ולא "אברהם").
```

### IDENTITY.md
```markdown
שמי: ארתור 🦞
```

**מגבלות:** כל קובץ מוגבל ל-20,000 תווים. סה"כ כל הקבצים: 150,000 תווים.

## זיכרון - איך הסוכן זוכר דברים

### עיקרון הזהב: "הזיכרון הוא קבצי Markdown"

OpenClaw לא שומר זיכרון בבסיס נתונים. **הכל בקבצים רגילים** שאתה יכול לקרוא, לערוך ולגבות ב-Git.

### סוגי זיכרון

**1. יומן יומי (memory/YYYY-MM-DD.md)**
- הסוכן כותב לכאן ביומיום
- נקרא אוטומטית: היום + אתמול
- מוסיפים מידע (לא מוחקים)

**2. MEMORY.md - זיכרון ארוך-טווח**
- מאורגן ומאוצר
- הסוכן מעדכן כשיש החלטות/העדפות חשובות
- זמין רק ב-session ראשי (DM פרטי)

### כלי זיכרון שהסוכן יכול להשתמש בהם
- `memory_search` - חיפוש סמנטי בזיכרון
- `memory_get` - קריאת קובץ ספציפי

### חיפוש וקטורי (אופציונלי)
OpenClaw יכול לבנות **אינדקס וקטורי** על קבצי הזיכרון:
- חיפוש לפי משמעות (לא רק מילות מפתח)
- תמיכה ב-OpenAI, Gemini, Voyage, Ollama ועוד
- BM25 + vector hybrid search

### Memory Flush לפני Compaction
לפני שה-session "מתכווץ" (כי חלון הקונטקסט מתמלא), OpenClaw מפעיל **turn שקט** שמבקש מהסוכן לכתוב מידע חשוב לדיסק - כדי שלא יאבד.

## Agent Loop - מה קורה בכל "ריצה"

```
1. הודעה נכנסת
2. בניית קונטקסט (System Prompt + קבצי Workspace + היסטוריה)
3. קריאה למודל AI
4. מודל מחזיר: טקסט ו/או קריאות לכלים
5. הרצת כלים (קריאת קבצים, גלישה, exec...)
6. חזרה ל-3 עד שאין עוד כלים
7. שליחת תשובה לערוץ
8. שמירת session ב-JSONL
```

### Hook Points - נקודות התערבות
Plugin יכול "להיכנס" לתהליך בנקודות שונות:
- `before_agent_start` - לפני שהסוכן מתחיל
- `before_tool_call` / `after_tool_call` - סביב כל כלי
- `message_received` / `message_sent` - סביב הודעות
- `before_compaction` / `after_compaction` - סביב כיווץ

**Timeout:** ברירת מחדל 600 שניות (10 דקות) לריצה אחת.
