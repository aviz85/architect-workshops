## הרעיון: סקיל קורא לסקיל (60 שניות)

### האנלוגיה:

חשבו על מפעל.
כל עובד יודע לעשות דבר אחד טוב.

- אחד יודע לעצב
- אחד יודע לכתוב
- אחד יודע לשלוח מיילים
- אחד יודע ליצור PDF

**עכשיו תארו מנהל שיודע לתאם ביניהם.**

"צריך הצעת מחיר" →
מנהל קורא לעיצוב → לכתיבה → ל-PDF → לשליחה

**זה בדיוק מה ש-Claude Code עושה עם סקילים.**

## איך בונים ערימה? (90 שניות)

### שלב 1: סקילים בסיסיים

קודם צריך שיהיו סקילים שעובדים לבד.
כל אחד עושה דבר אחד טוב.

### שלב 2: סקיל מתאם (Orchestrator)

יוצרים סקיל חדש שמתאר את התהליך המלא:

```markdown
# send-full-proposal

## מתי להשתמש
כשמבקשים לשלוח הצעת מחיר מלאה ללקוח.

## התהליך
1. השתמש ב-get-client-info כדי למשוך את פרטי הלקוח
2. השתמש ב-create-proposal כדי לכתוב את ההצעה
3. השתמש ב-generate-pdf כדי ליצור PDF מעוצב
4. השתמש ב-send-email כדי לשלוח ללקוח
5. שמור עותק בתיקיית documents/proposals/

## פרמטרים
- שם הלקוח (חובה)
- תיאור הפרויקט (חובה)
- מחיר (אופציונלי - אם לא ניתן, תחשב לפי מחירון)
```

### שלב 3: Claude מבין

עכשיו כשאומרים "תשלח הצעה לחיים" -
Claude מזהה את הסקיל המתאם,
ומריץ את כל השרשרת אוטומטית.

## טיפים לבניית ערימות (45 שניות)

### 1. התחילו קטן
קודם סקיל אחד → אז שניים → אז ערימה

### 2. בדקו כל שלב
וודאו שכל סקיל עובד לבד לפני שמחברים

### 3. תעדו את התהליך
כתבו בדיוק מה כל שלב עושה

### 4. טפלו בשגיאות
```markdown
## אם נכשל
- אם לא נמצא לקוח: שאל את המשתמש
- אם אין מחיר: השתמש במחירון ברירת מחדל
- אם השליחה נכשלה: שמור טיוטה ודווח
```

### 5. צרו לוגים
```markdown
## לאחר הביצוע
שמור רשומה ב-logs/proposals.md עם תאריך, לקוח, וסטטוס
```
