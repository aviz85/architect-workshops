## הסיכונים האמיתיים (90 שניות)

### סיכון 1: מחיקה לא מכוונת

**הבעיה:**
```
> "נקה את התיקייה מקבצים ישנים"
[Claude מוחק משהו שלא התכוונתם]
```

**הפתרון:**
- בקשו לראות לפני מחיקה
- שמרו גיבויים
- עבדו ב-git (אפשר לשחזר)

### סיכון 2: שליחה לא נכונה

**הבעיה:**
```
> "שלח את ההצעה לכל הלקוחות"
[Claude שולח גם לאנשים שלא צריך]
```

**הפתרון:**
- בקשו לראות רשימה לפני שליחה
- הגדירו כללים בסקיל ("לא לשלוח ל-VIP בלי אישור")

### סיכון 3: חשיפת מידע רגיש

**הבעיה:**
```
> "שתף את הפרויקט ב-GitHub"
[Claude מעלה קובץ עם API keys]
```

**הפתרון:**
- קובץ `.gitignore` תמיד
- לא לשמור מפתחות בקוד
- לבדוק לפני push

### סיכון 4: אמון יתר

**הבעיה:**
```
> "תעשה מה שנראה לך הכי טוב"
[Claude מחליט משהו שאתם לא רוצים]
```

**הפתרון:**
- הנחיות ספציפיות
- לא "תעשה מה שנראה לך" אלא "תעשה X, Y, Z"

## Best Practices לאבטחה (90 שניות)

### 1. עבדו עם Git

```bash
git init
git add .
git commit -m "before claude experiment"
```

אם משהו משתבש - `git reset --hard`

### 2. הגדירו .gitignore

```
.env
*.key
credentials/
secrets/
```

### 3. API Keys בקובץ נפרד

לא ככה:
```markdown
# CLAUDE.md
API_KEY=abc123secret
```

ככה:
```markdown
# CLAUDE.md
ראה .env לגבי API keys
```

### 4. סקרו לפני שליחה

```
> "הראה לי מה אתה הולך לשלוח לפני ששולח"
```

### 5. הגבילו ב-Skills

```markdown
## הגבלות אבטחה
- לא לשלוח ליותר מ-10 אנשים בבת אחת
- לא לגשת לתיקיית finances/
- לא להריץ פקודות sudo
```

### 6. גבו תמיד

לפני ניסויים גדולים - גבו את התיקייה.

## שאלות נפוצות (45 שניות)

### "האם Anthropic רואים את הקבצים שלי?"

**לא.** Claude עובד על המחשב שלכם.
Anthropic רואים את השיחה (לשיפור), לא את הקבצים.

### "מה אם Claude ישתגע?"

Claude לא "משתגע". הוא מבצע הנחיות.
אם התוצאה לא טובה - ההנחיות לא היו מספיק ברורות.

### "האם לסמוך על מצב חללית?"

כן, אחרי שבדקתם את התהליך ידנית.
**קודם ידני, אחרי אוטונומי.**

### "מה עם האקרים?"

Claude לא פותח פורטים או מאזין לחיבורים.
הסיכון שלו לא שונה מכל תוכנה אחרת.
