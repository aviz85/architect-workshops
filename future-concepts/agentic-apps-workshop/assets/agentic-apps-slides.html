באפליקציה קלאסית, אנחנו כותבים אלגוריתמים ותנאים.

ב-Agentic App, מסמכים כתובים מחליפים את הקוד.

שתי גישות - שתי מציאויות

Classic App

Runtime: Node.js, Python

לוגיקה: אלגוריתמים, if/else

מסד נתונים: PostgreSQL

ממשק: React, Vue

Agentic App

Runtime: Claude Code Agent

לוגיקה: Skills, Commands

מסד נתונים: קבצי Markdown

ממשק: Chat / UI עטיפה

מה קורה כשלוחצים על כפתור?

Classic App:

Button Click → Call Function → Execute Code → Update DB

Agentic App:

Button Click → Send /command → Agent Decides → Update Docs

הסוכן מקבל החלטות - לא רק מבצע פקודות

כל מה שהכרתם - בגרסה חדשה

  • קונפיגורציה: config.yaml → CLAUDE.md
  • ספריות: npm packages → Skills
  • API Endpoints: REST routes → /commands
  • Background Jobs: Cron → Sub-agents
  • Deployment: Docker, K8s → cd folder
  • זמן בנייה: שבועות-חודשים → שעות-ימים

חלק 2: אבני הבניין

5 רכיבים שמרכיבים אפליקציה שלמה

  • CLAUDE.md - החוקה
  • Skills - יכולות אוטומטיות
  • Commands - פעולות מפורשות
  • Agents - תהליכים מורכבים
  • Data Files - המידע

CLAUDE.md - החוקה של האפליקציה

קובץ אחד שמגדיר הכל:

  • מי האפליקציה ומה היא עושה
  • חוקים והנחיות התנהגות
  • קונפיגורציה והגדרות
  • קשרים בין רכיבים
אנלוגיה: config.yaml + README + business rules

Skills - יכולות אוטומטיות

Skills הם "ספריות" של הסוכן:

  • פעולות מורכבות ארוזות ומוכנות
  • הסוכן מפעיל אותן אוטומטית כשצריך
  • אפשר לשתף Skills בין פרויקטים
  • כמו npm packages - אבל בשפה טבעית
אנלוגיה: npm/pip packages, middleware

Commands - פעולות מפורשות

Commands הם ה-API של האפליקציה:

  • פקודות שהמשתמש מפעיל במפורש
  • מתחילות ב-/ (slash)
  • כל כפתור ב-UI = פקודה
  • פשוטות ליצירה ולשינוי
אנלוגיה: REST API endpoints

Agents - תהליכים מורכבים

Agents הם "עובדים" שמבצעים משימות:

  • תהליכים שרצים ברקע
  • מפעילים skills ו-commands
  • יכולים לקבל החלטות
  • מושלמים למשימות מורכבות
אנלוגיה: Background workers, cron jobs

Data Files - המידע של האפליקציה

קבצי Markdown = מסד נתונים:

  • קריאים לבני אדם
  • גרסאות ב-Git
  • קלים לעריכה ידנית
  • הסוכן קורא וכותב אותם
אנלוגיה: PostgreSQL, MongoDB - אבל קריא!

5 רכיבים = אפליקציה שלמה

  • CLAUDE.md → חוקה + הגדרות (config + README)
  • Skills → יכולות אוטומטיות (ספריות, middleware)
  • Commands → פעולות מפורשות (API endpoints)
  • Agents → תהליכים מורכבים (background workers)
  • Data Files → מצב האפליקציה (database)
עכשיו נראה את זה בפעולה!

מבנה הפרויקט שלנו

  • .claude/commands/ - פקודות משתמש
  • .claude/skills/ - יכולות אוטומטיות
  • .claude/agents/ - תהליכים מורכבים
  • data/customers/ - תיקיות לקוחות
  • data/interactions.md - לוג אינטראקציות
כל שורה = רכיב שלמדנו!

שלב 1: יצירת CLAUDE.md

הגדרת המערכת:

  • Purpose: מערכת CRM לניהול לקוחות
  • Rules: לקוח חדש = Active, 7 ימים = follow-up
  • Data Structure: /data/customers/, interactions.md
  • Commands: /add-customer, /log-interaction, /followup

שלב 2: יצירת /add-customer

מה הפקודה עושה:

  • מקבלת שם ואימייל
  • יוצרת קובץ לקוח חדש
  • מוסיפה תאריך יצירה
  • מגדירה סטטוס Active
Usage: /add-customer [שם] [אימייל]

שלב 3: יצירת /log-interaction

מה הפקודה עושה:

  • מתעדת שיחה עם לקוח
  • מעדכנת את קובץ הלקוח
  • מוסיפה לטבלת האינטראקציות
  • מאפסת את ספירת ה-follow-up
Types: Call, Email, Meeting, Note

שלב 4: יצירת /followup

מה הפקודה עושה:

  • סורקת את כל הלקוחות
  • מזהה לקוחות ללא אינטראקציה 7+ ימים
  • מציגה רשימה מתועדפת
  • מציעה פעולות המשך

שלב 5: יצירת customer-analysis skill

מה ה-Skill עושה:

  • מנתח היסטוריית לקוח
  • מחשב ציון מעורבות (0-100)
  • מזהה דפוסים
  • מפיק דו"ח מסכם

שלב 6: יצירת weekly-review agent

מה ה-Agent עושה:

  • רץ אוטומטית כל שבוע (יום ראשון 09:00)
  • מרכז נתונים מכל הלקוחות
  • מייצר דו"ח שבועי
  • מזהה לקוחות בסיכון
