CLAUDE.md

החוקה של האפליקציה

קובץ אחד שמגדיר הכל:

  • מי האפליקציה ומה היא עושה
  • חוקים והנחיות התנהגות
  • קונפיגורציה והגדרות
  • קשרים בין רכיבים

אנלוגיה:

config.yaml + README + business rules

# My CRM App ## Purpose מערכת ניהול לקוחות לעסק קטן ## Rules - תמיד שמור על נימוס בתקשורת - אל תמחק לקוחות - סמן כלא פעילים - שלח תזכורת follow-up אחרי 7 ימים ## Structure - /data/customers - תיקיות לקוחות - /data/interactions.md - לוג שיחות

Skills

יכולות אוטומטיות

Skills הם "ספריות" של הסוכן:

  • פעולות מורכבות ארוזות ומוכנות
  • הסוכן מפעיל אותן אוטומטית כשצריך
  • אפשר לשתף Skills בין פרויקטים
  • כמו npm packages - אבל בשפה טבעית

אנלוגיה:

npm/pip packages, middleware

.claude/skills/customer-analysis/ ├── skill.md │ "כשמבקשים ניתוח לקוח: │ 1. קרא את כל האינטראקציות │ 2. חשב ציון מעורבות │ 3. זהה דפוסי רכישה │ 4. צור דו״ח מסכם" │ └── templates/ └── report-template.md

Commands

פעולות מפורשות

Commands הם ה-API של האפליקציה:

  • פקודות שהמשתמש מפעיל במפורש
  • מתחילות ב-/ (slash)
  • כל כפתור ב-UI = פקודה
  • פשוטות ליצירה ולשינוי

אנלוגיה:

REST API endpoints

$ /add-customer שם אימייל → הוסף לקוח חדש למערכת $ /log-interaction לקוח סוג תוכן → תעד שיחה עם לקוח $ /followup → הצג לקוחות שצריכים follow-up $ /analyze-customer לקוח → נתח לקוח והפק דו״ח

Agents

תהליכים מורכבים

Agents הם "עובדים" שמבצעים משימות:

  • תהליכים שרצים ברקע
  • מפעילים skills ו-commands
  • יכולים לקבל החלטות
  • מושלמים למשימות מורכבות

אנלוגיה:

Background workers, cron jobs

# Weekly Review Agent ## Trigger כל יום ראשון בבוקר ## Tasks 1. סרוק את כל הלקוחות 2. זהה לקוחות ללא אינטראקציה בשבוע 3. צור רשימת follow-up מתועדפת 4. שלח סיכום למנהל ## Output /data/reports/weekly-YYYY-MM-DD.md

Data Files

המידע של האפליקציה

קבצי Markdown = מסד נתונים:

  • קריאים לבני אדם
  • גרסאות ב-Git
  • קלים לעריכה ידנית
  • הסוכן קורא וכותב אותם

אנלוגיה:

PostgreSQL, MongoDB - אבל קריא!

/data/ ├── customers/ │ ├── acme-corp.md │ │ "# ACME Corp │ │ Status: Active │ │ Contact: john@acme.com │ │ Score: 85" │ │ │ └── beta-inc.md │ └── interactions.md "| Date | Customer | Type | | 2024-01-15 | ACME | Call | | 2024-01-16 | Beta | Email |"

יצירת CLAUDE.md

# My CRM - מערכת ניהול לקוחות ## Purpose מערכת CRM פשוטה לניהול לקוחות ומעקב אחרי אינטראקציות. ## Business Rules - לקוח חדש מקבל סטטוס "Active" - אחרי 7 ימים ללא אינטראקציה - סמן ל-follow-up - אל תמחק לקוחות - סמן כ-"Inactive" - כל אינטראקציה נרשמת עם תאריך וסוג ## Data Structure - /data/customers/ - קובץ לכל לקוח - /data/interactions.md - טבלת אינטראקציות ## Available Commands - /add-customer - הוספת לקוח חדש - /log-interaction - תיעוד אינטראקציה - /followup - רשימת לקוחות ל-follow-up

שלב 2 מתוך 6

יצירת /add-customer

מה הפקודה עושה:

  • מקבלת שם ואימייל
  • יוצרת קובץ לקוח חדש
  • מוסיפה תאריך יצירה
  • מגדירה סטטוס Active
# Add Customer Command ## Usage /add-customer [שם] [אימייל] ## Steps 1. צור קובץ חדש: /data/customers/[שם].md 2. הוסף פרטים: - Name: [שם] - Email: [אימייל] - Status: Active - Created: [תאריך היום] 3. אשר למשתמש

שלב 3 מתוך 6

יצירת /log-interaction

מה הפקודה עושה:

  • מתעדת שיחה עם לקוח
  • מעדכנת את קובץ הלקוח
  • מוסיפה לטבלת האינטראקציות
  • מאפסת את ספירת ה-follow-up
# Log Interaction Command ## Usage /log-interaction [לקוח] [סוג] [תוכן] ## Interaction Types - Call (שיחה) - Email (מייל) - Meeting (פגישה) - Note (הערה) ## Steps 1. הוסף שורה ל-interactions.md 2. עדכן Last Contact בקובץ הלקוח 3. אשר למשתמש

שלב 4 מתוך 6

יצירת /followup

מה הפקודה עושה:

  • סורקת את כל הלקוחות
  • מזהה לקוחות ללא אינטראקציה
  • מציגה רשימה מתועדפת
  • מציעה פעולות המשך
# Follow-up Command ## Usage /followup ## Logic 1. קרא את כל קבצי הלקוחות 2. חשב ימים מאז Last Contact 3. סנן לקוחות עם 7+ ימים 4. מיין לפי ימים (יורד) ## Output Format | לקוח | ימים | סוג אחרון | | ACME | 12 | Call | | Beta | 8 | Email |

# Customer Analysis Skill ## When to Use כשהמשתמש מבקש "נתח לקוח" או "תן לי מידע על לקוח" ## Analysis Steps 1. קרא את כל האינטראקציות 2. חשב: - סה"כ אינטראקציות - ממוצע אינטראקציות/חודש - סוג אינטראקציה נפוץ 3. חשב ציון מעורבות (0-100) 4. צור דו"ח מסכם

הוספת UI עם Agent SDK

כשצ׳אט לא מספיק

מתי להוסיף UI?

✅ CLI מספיק כש...

  • המשתמש טכני
  • כלים פנימיים אישיים
  • פרוטוטייפים מהירים
  • אוטומציות ברקע

🎨 צריך UI כש...

  • משתפים עם משתמשים לא טכניים
  • צריך דשבורדים ודוחות
  • בונים מוצר ללקוחות
  • רוצים חוויה ויזואלית

Agent SDK - הבסיס

Agent SDK מאפשר:

  • לחבר UI (React, Vue, HTML) לסוכן
  • לשלוח /commands מכפתורים
  • לקרוא data files ולהציג בדשבורד
  • הסוכן נשאר המוח - UI רק עטיפה
from claude_agent_sdk import query async def add_customer(name, email): result = await query( prompt=f"/add-customer {name} {email}", options={ "working_directory": "./my-crm" } ) return result

כפתור → /command → סוכן מחליט → תוצאה
